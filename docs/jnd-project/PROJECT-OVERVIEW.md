# Project Overview

## Business and website

- Business: Just Needs Done Enterprises, LLC
- Public website: <https://justneedsdone.com>
- Repository: `justneedsdone-sketch/jnd-site`
- Default branch: `main`
- Framework: Astro 5.16.11
- Rendering model: static Astro output
- Package manager state: npm lockfile version 3; installed dependencies were present during inspection

## Deployment setup

The GitHub repository is connected to the live deployment. The repository's default branch and the inspected local branch are both `main`. No GitHub Actions workflow, Pages configuration, `wrangler.toml`, Netlify file, Vercel file, or other deployment configuration is tracked in this repository.

The live site is served through Cloudflare and matches the current Astro 5.16.11 output. Repository content also refers to Cloudflare “Work” posts. The evidence supports an externally configured, GitHub-connected Cloudflare deployment, most likely Cloudflare Pages. The exact Cloudflare product, production branch, build command, output directory, environment variables, and fallback rules cannot be confirmed from this repository and should be verified in the Cloudflare account before deployment settings are changed.

Important deployment findings:

- `astro.config.mjs` incorrectly sets `site` to `https://example.com`, so live canonical, RSS, Open Graph, Twitter, and sitemap URLs use the wrong domain.
- The Cloudflare-facing site returns the home page with HTTP 200 for unknown routes, including `/work/` and a deliberately nonexistent audit path. This hides 404s and can create duplicate-content/SEO problems.
- GitHub reports no commit statuses or pull-request workflow runs for the inspected head commit, and there are no tracked CI workflows.

## Shared layouts and components

- `src/layouts/Layout.astro` provides `BaseHead`, `Header`, a slotted `main`, and `Footer` for Home, Services, and Gallery.
- `src/layouts/BlogPost.astro` provides the template for About and individual blog posts.
- `src/components/BaseHead.astro` imports global CSS and produces canonical, RSS, Open Graph, and Twitter metadata.
- `src/components/Header.astro` provides the JND logo, primary navigation, and inline Facebook icon.
- `src/components/HeaderLink.astro` calculates the active navigation state.
- `src/components/Footer.astro` provides copyright, tagline, and email.
- `src/components/FormattedDate.astro` formats blog dates.
- `src/pages/contact.astro` manually assembles `BaseHead`, `Header`, and `Footer` instead of using `Layout.astro`.
- `src/pages/blog/index.astro` also manually assembles the page shell.

## Major integrations

- `@astrojs/mdx` for the retained MDX sample post
- `@astrojs/rss` for `/rss.xml`
- `@astrojs/sitemap` for generated sitemap files
- `sharp` for Astro image processing
- Facebook page links throughout the JND pages
- Facebook post plugin iframe on Gallery
- Google Maps search links on Home and Contact
- Email quote links using `mailto:`
- Cloudflare at the public delivery/deployment layer; exact account-side configuration is not versioned

There is no form processor, CMS integration, analytics integration, database, or client-side JavaScript application in the tracked source. The Gallery text describes a future automatic `/work` workflow, but no implementation exists in this repository.

## Current development status

The site is live and its four primary pages have branded navigation, basic service/contact content, and functional email/Facebook/Maps destinations. It remains a partially customized Astro starter: production metadata is misconfigured, template routes/assets are public, approved colors and fonts are not implemented, the Gallery workflow is incomplete, the main JND pages have inconsistent width/layout behavior, and one Services CSS block is malformed.
